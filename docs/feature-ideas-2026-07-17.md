# Feature ideas: Meal Move — backlog (2026-07-17)

Generated by the `feature-ideation` skill, grounded in a survey of PRODUCT.md /
DESIGN.md / CLAUDE.md, the `app/` route tree, `prisma/schema.prisma`, and the
`lib/` logic modules. Ranked by need + impact, with honest effort estimates.
These are **ideas, not decided work** — pick one and take it into brainstorming
before building.

## The gaps found

1. **Restaurants get no push when their food is claimed or delivered.**
   `notify.ts` defines `restaurantMemberIds()` for exactly this, but nothing
   calls it. Push fires only for buddy invites, broadcasts, drop-off notices,
   announcements. A restaurant learns of a rescue only by opening
   `/restaurant/listings`. Directly under the restaurant trust need.
2. **Operational memory has no home.** `orgNotes` = partner relationships;
   `AdminEvent` = audit log. Neither holds *how the chapter is run*. Failure
   mode #2 (founder turnover), least served.
3. **`NeedLevel` drives nothing.** On `DropOff`, shown on the map, but
   `lib/recommend.ts` ranks drop-offs by eligibility + distance only.
4. **Drop-offs can only receive, never ask.** Routes are incoming / impact /
   conversations — all passive. No way to signal demand.
5. **No proactive "still coming?" before a flake.** `lib/checkins.ts` is release
   mechanics only; the sweep logs the flake after the hold lapses.
6. **Admin succession has no on-ramp.** `lib/onboarding.ts` is a volunteer's
   first-rescue tracker; a new org admin inherits nothing.

## Ideas, ranked

1. **Restaurant claim & delivery notifications** — push on claim + delivery,
   reusing the already-written `restaurantMemberIds` fan-out and existing
   dispatch path. *Gap 1. Effort: small.* Strongest for how cheap it is — the
   code exists and is unused.
2. **Need-aware drop-off ranking** — fold `NeedLevel` into `rankDropOffs` so
   higher-need drop-offs surface first in the claim picker, with a "needs food
   now" cue. *Gap 3. Effort: small.*
3. **Chapter playbook** — editable operational-memory surface in the admin
   console (routines, escalation, decisions + rationale, seasonal notes),
   seeded from partners/recurring posts/admins. *Gap 2. Effort: medium.*
4. **Gentle pre-expiry nudge, with buddy cover** — as a claim nears its hold with
   no progress, nudge volunteer + buddy ("your buddy can cover if not").
   Non-punitive. *Gap 5. Effort: small–medium.*
5. **Standing drop-off requests** — let a drop-off post a standing/one-off need,
   surfaced to admins and to restaurants when they post. `rankRestaurantsForDropOff`
   is the matching seed. *Gap 4. Effort: medium.*
6. **Chapter handoff pack for a new admin** — a "you're now running this chapter"
   briefing (active partners, volunteers + standing, recurring commitments,
   pointer into the playbook). Pairs with #3. *Gap 6. Effort: medium.*

## Ruled out (already built or anti-goal)

- Leaderboard / points / grades — explicit anti-goal in the docs.
- Restaurant live rescue-stage view — already built (`RestaurantListings`).
- Escalating urgency broadcast, recurring posts, holds/buddies, photo proof,
  chapter health metrics — already built.
- Generic notifications center — FCM/priming/quiet-hours already exist.
